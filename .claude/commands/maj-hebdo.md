---
description: Passe hebdomadaire (sondages, périmètre, liens, veille) livrée en pull request
---

Passe hebdomadaire de mise à jour, menée seul, sans interlocuteur. Ne rien publier sur `main` : tout passe par une pull request que l'utilisateur relira. Rester sobre : une ou deux recherches web par candidat pour la veille.

0. **Préparer** : `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`, puis `cd frontend && npm ci`. Créer la branche `maj-hebdo/<date du jour>`.
1. **Sondages** : suivre `.claude/commands/maj-sondages.md`. Si le site de la Commission des sondages est injoignable (curl, puis WebFetch), n'ajoute rien et signale-le : ne conclus jamais « aucune nouvelle notice » sans avoir pu lire la liste des notices.
2. **Périmètre** (`content/perimetre.json`) : appliquer la règle du champ `regle`. Ajouter les déclarations formelles ou désignations nouvelles, noter les retraits, mettre à jour les sources de sondage de chaque candidature (fenêtre de 60 jours) et `maj`. Ne pas créer ni supprimer de fiche : le signaler dans la pull request. Ne modifie `perimetre.json`, y compris `maj`, que si tu as réellement réexaminé le périmètre à partir des notices ; sinon laisse le fichier tel quel et dis-le.
3. **Liens** : `.venv/bin/python -m tools.check_links`, lancé avec `run_in_background` : il vérifie environ 280 liens et dure de 3 à 5 minutes. Il affiche les liens défaillants au fil de l'eau puis une ligne finale « N/M liens OK » ; tant que cette ligne n'est pas apparue, il n'a pas fini et tu ne dois pas conclure. Tu ne l'interromps jamais, et tu n'écris dans la pull request que des durées que tu as mesurées. Remplacer l'URL d'un document qui a seulement changé d'adresse ; signaler les autres. Faux positifs connus : `fr.timesofisrael.com` et `blog.landot-avocats.net` répondent 403 aux scripts mais s'ouvrent dans un navigateur.
4. **Veille** : pour chaque fiche de `content/candidatures/`, chercher les événements survenus depuis sa date `maj` : programme publié ou mis à jour, mesure majeure annoncée, changement de statut de candidature, affaire judiciaire nouvelle ou jugée. Tenir compte des échéances de `SUIVI.md`. Ne PAS modifier les fiches : mettre à jour `SUIVI.md` (date de la veille, échéances passées retirées, nouvelles échéances, fiches à reprendre avec la raison et le lien de la source).
5. **Vérifier** : `.venv/bin/python -m pytest`, puis `cd frontend && npm test && npm run build`.
6. **Livrer** : commiter, pousser la branche et ouvrir une pull request vers `main` intitulée « Mise à jour hebdomadaire du <date> ». La description liste les sondages ajoutés, les changements de périmètre, les liens corrigés ou cassés et les fiches à reprendre (raison et source), pour que l'utilisateur lance ensuite `/maj-fiche <id>` sur celles qu'il choisit.
